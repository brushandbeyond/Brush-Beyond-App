Subject: Child-directed iOS designation before first App Store publication: no published apps / verification returns to start

We are trying to designate our iOS education app as child-directed using Google's official tool at https://coppa.developers.google.com/selfdeclaration/ios/home.

App: Brush & Beyond
Bundle ID: net.brushbeyond.app
Apple app ID: 6832145033
Apple status: Prepare for Submission; not yet publicly released.

Reproduction:

1. Sign in with our organization Google account.
2. Select JWT / Use a token generated by you.
3. Enter a freshly generated ES256 Apple App Store Connect team-key JWT (correct issuer/key identifiers, appstoreconnect-v1 audience, lifetime five minutes or less).
4. Select Next.
5. The page briefly navigates to /selfdeclaration/ios/apps, then returns to /selfdeclaration/ios/home without showing an app list or a visible error. No tag can be applied.

This reproduced in the in-app browser and, as reported by the owner, Safari. We tested an App Manager key and then a separate Developer key, as the tool recommends. Both keys were accepted by Apple for direct app-metadata reads, with the intended app present in Apple's app list.

Latest owner-reported result: the tool displays “You don’t appear to have any published apps for this account.” Our app has not had its first public App Store release. This suggests a possible publication-status limitation, but we have not established the cause. We want to complete the child-directed designation before exposing children to the embedded player in a public release.

The tokens are deliberately scoped to read-only app metadata. One restriction we identified: a plain GET /v1/apps scope returns HTTP 200 for the plain endpoint but HTTP 403 FORBIDDEN.REQUEST_DOES_NOT_MATCH_SCOPE for requests adding fields[apps]=name,bundleId. Adding that exact read-only query scope yields HTTP 200 with our app present. Retrying Google's tool with this additional verified scope still returned to the start page. We do not know which request or check Google's tool rejects; this is not proof of a Google service outage. We have not sent an unrestricted token or a persistent private key to Google as a workaround.

Please advise:

- Which Apple endpoints/query parameters and JWT scopes does this ownership-verification tool require?
- Are short-lived, explicitly scoped read-only JWTs supported?
- Can an app in Prepare for Submission be tagged before its first public App Store release?
- Does Apple approval with manual release (approved but not publicly available) make the app eligible? If public availability is necessary, what supported pre-launch designation process should a child-directed app use?
- How can we retrieve a diagnostic error or obtain assistance tagging the app without exposing a persistent private key or granting unnecessary write access?

No private keys, bearer tokens, authorization headers, raw HAR files, or personal account data are included in this report. They should not be added to a public issue.
